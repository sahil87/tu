# Formatting & Display

## Overview

The formatting layer (`src/node/tui/formatter.ts`) renders token usage data into terminal tables with ANSI colors. It supports three table layouts plus compact variants for narrow terminals. The color system (`src/node/tui/colors.ts`) provides NO_COLOR-compliant ANSI wrappers.

## Requirements

- Three table layouts MUST be supported:
  1. **Single-tool history** (`renderHistory`): date rows with token breakdown (input, output, cache write, cache read, total) plus cost column and inline bar chart
  2. **Cross-tool snapshot** (`renderTotal`): tool rows with tokens, input, output, combined cache (write + read), cost
  3. **Cross-tool history pivot** (`renderTotalHistory`): date rows x tool columns showing costs, with total cost column and bar chart
- Each layout MUST have both `render*` (returns `string[]`) and `print*` (console.log) variants
- Inline bar charts MUST use Unicode block characters at eighths precision (U+2588-U+258F)
- Bar width MUST auto-scale based on terminal width with 10-char minimum and 30-char maximum
- Delta indicators (up/down arrows) MUST show when `prevCosts` map is provided (for watch mode)
- Compact mode (date + cost only) MUST activate when terminal width < 60
- Colors MUST respect `NO_COLOR` env var and `--no-color` flag via `setNoColor()`
- Available color functions: `bold`, `dim`, `green`, `red`, `cyan`, `yellow`, `magenta`, `blue`, `boldWhite`, `boldCyan`, `brightGreen`, `dimGreen`; the `colorDisabled()` accessor reports whether color output is off (260816-3tah)
- `stripAnsi()` MUST be available for measuring visible string length
- Total row MUST only render when more than one tool has visible data (`totalTokens > 0`) — applies to all snapshot layouts: `renderTotal`, `renderCompactSnapshot`
- The cross-tool snapshot (`renderTotal`) MUST render a combined `Cache` column (`cacheCreationTokens + cacheReadTokens`) between `Output` and `Cost`, so the visible numeric columns close arithmetically (`Input + Output + Cache = Tokens`); a zero-cache tool renders `0` and the Total row sums the column. Snapshot fixed widths are 12 for the Tool column and 12 for each numeric column — the full row (`Tool | Tokens | Input | Output | Cache | Cost`) measures exactly **87 visible chars** (`12 + 5×12 + 5×3`), within the ≤90 budget. Machine columns keep appending after `Cost` (letter-coded, data-sized with a 9-char floor). The watch loading skeleton (`renderSkeleton` in `src/node/tui/watch.ts`) mirrors the same column set and widths so it aligns with the first real frame. The Markdown snapshot emitter carries the same `Cache` column; the CSV snapshot gains a `cache` column after `output` (see the `emitCsv` bullet). JSON, compact mode, and single-tool history are unchanged (260815-nda3)
- The cross-tool history pivot (`renderTotalHistory`) MUST size each tool column individually to `max(toolName.length, MIN_TOOL_COL_WIDTH, longest fmtCost() cell in the column including its Total-row sum)` (floor `9`) with a Date column of `PIVOT_DATE_WIDTH` (`10`), and MUST size its Cost column from every row cost plus the grand total via the shared `costColumnWidth` helper (floor `COST_WIDTH`). The `row`/`colorRow` cell builders, the `divStr` divider, and `tableWidth` all consume one shared per-column width array. The **full data row** — Date + all tool columns + the 3-char gutter + the Cost cell — measures a **minimum of 96 visible chars** for the six-tool registry (`10 + (11+9+9+9+9+9) + 6×3 + 3 + 9`, holding whenever every cell fits within `$9,999.99`) before negligible-column omission; a larger cell widens its own column from there. With omission applied, the typically rendered row is far below 80 chars. The width contract is the full row through the Cost cell, not body-only fit (260703-gmcp, widths 260815-q6fx, data-sizing 260828-7x4i)
- In watch mode the pivot's delta indicator MUST be rendered **space-less** (`$128.13↑` — the arrow abuts the Cost cell, adding 1 visible char) rather than the ` ↑`/` ↓` spaced form every other renderer uses. `deltaIndicator(current, key, prevCosts, noSpace)` takes a `noSpace` param; `renderTotalHistory` passes `noSpace = true`, all other call sites keep the spaced form. This keeps the minimum watch-mode full row at **96 + 1 = 97**, fitting a 97-col terminal — the spaced 2-char form would add one more char and wrap every row at that width, corrupting the watch-mode compositor's line-counting (260703-gmcp, widths 260815-q6fx, 260828-7x4i)
- The pivot's bar-area budget MUST reserve **1 extra char** (`indicatorReserve`) when `opts.prevCosts` is set: `barWidth = min(width − tableWidth − GUTTER − costWidth − 1 − indicatorReserve, MAX_BAR_WIDTH)`, where `costWidth` is the data-sized Cost column — all column widths are computed from the pre-collected row data before the bar budget is derived. Without it, the space-less indicator pushes the max-cost row to `width + 1` across the bars band (~97+ cols, where bars render) and wraps it; the reserve keeps every bars-band row within the terminal width (260703-gmcp, 260828-7x4i)
- The ANSI pivot (`renderTotalHistory`) MUST select its tool columns via the shared `significantCostTools` helper: a column is kept iff its total cost across the visible labels (the post-`maxRows` window) is `≥ NEGLIGIBLE_COST_ABS` ($1.00) **and** `≥ NEGLIGIBLE_COST_SHARE` (0.001) × the window grand total — boundary values are kept. When the filter would empty the set it falls back to `nonzeroCostTools` (exact-zero), which itself falls back to the unfiltered registry list. The Markdown emitter (`emitMarkdownTotalHistory`) keeps the exact-zero rule (`nonzeroCostTools`, over all its labels). A single remaining tool keeps the pivot shape (Date | Tool | Cost) — no collapse to the single-tool layout. The CSV emitter MUST NOT filter: CSV is a positional machine contract and keeps every registry column with raw `0.00` cells. Omission affects only the visible columns and their legend swatches: `rowCost`, `grandTotal`, `barTotal` and the footer MUST sum over **all** registry tools, while `cells`/`toolBars`/`toolSums`/legend/palette use the visible set, and `apportionSegments` absorbs an omitted tool's share by normalising over the shares it receives (260815-q6fx, significance rule 260828-7x4i)
- Human-facing cost cells MUST render thousands separators: `fmtCost` returns `$${n.toLocaleString("en-US", { minimumFractionDigits: 2, maximumFractionDigits: 2 })}` (e.g. `$4,031.61`), propagating to every ANSI renderer and to `mdCost`. `csvCost` stays raw `toFixed(2)` per the CSV machine contract. Right-aligned cost columns (the pivot Cost column, `renderHistory`'s Cost column, `renderHistory`/`renderTotal` machine columns) MUST be sized from their data via the shared `costColumnWidth(values)` helper — `max(COST_WIDTH, longest fmtCost() among the values the column will hold, including its Total-row value)` — with `COST_WIDTH = 9` and `MACHINE_COL_WIDTH` (aliased to `COST_WIDTH`) as floors, so a render whose cells all fit 9 chars is byte-identical to a fixed 9-wide column. All machine columns share one width. The snapshot's own Cost cell lives in the fixed 12-wide numeric column (`fmtCostDelta`) and does not data-size. `COMPACT_COST_W` is 12 (fits `$99,999.99`) (260815-q6fx, data-sizing 260828-7x4i)
- A cost **data cell** whose value is exactly `0` MUST render its already-padded text through `dim()` via the shared `costCell(cost, width)` helper — pad first, then color, so the `row()`/`colorRow()` `padStart` (which pads by raw string length and would count ANSI bytes) is a no-op. This applies to the pivot's per-tool cells and row Cost cell, `renderHistory`'s Cost and machine cells, and `renderTotal`'s machine cells. The Total row (every cell stays `boldWhite`), headers and dividers are never dimmed; a sub-cent nonzero cost that formats as `$0.00` is not dimmed (the test is `=== 0`, not the formatted string). `dim` adds only escape bytes, so `stripAnsi` length is unchanged and `--no-color`/`NO_COLOR` output is byte-identical to an undimmed render (260828-7x4i)
- When the implicit 3-month history cap is active (see `cli/data-pipeline.md`), history table headings MUST carry a `last 3 months` hint appended inside the period parenthetical — `📊 Claude Code (daily, last 3 months)` (single-tool `renderHistory`), `📊 Combined Cost History (daily, last 3 months)` (cross-tool `renderTotalHistory`), and the Markdown `## {title}` heading (`titleForHistory`/`titleForTotalHistory`). The hint is threaded via an optional `capActive?: boolean` field on both `FormatOptions` and `EmitOptions`, consumed **only** at the heading-render points through a shared `periodLabel(period, capActive)` helper (`capActive ? \`${period}, last 3 months\` : period`) — NOT by mutating the `period` string handed to renderers, because `period` drives `currentLabel`/`aggregateForPeriod`/label logic and must stay pure. The hint MUST be absent when the cap is inactive (`--full`, explicit `--since`/`--until`, monthly, or snapshot). CSV/JSON have no heading, so no hint appears there — the cap still applies to their data via the defaulted `sinceFlag` (260717-yuuj)
- Watch mode uses the same `render*` functions as non-watch mode — no side-by-side merge or layout transformation is applied by the formatter
- When `FormatOptions.machineCosts` is provided (`Map<string, Map<string, number>>`, keyed by label/toolName → machine → cost), `renderHistory` and `renderTotal` MUST append letter-coded machine cost columns (A, B, C...) after the Cost column, all sharing one data-sized width — `max(MACHINE_COL_WIDTH, longest fmtCost() among every machine cell and every per-machine Total)` via `costColumnWidth`, floored at `MACHINE_COL_WIDTH` (aliased to `COST_WIDTH`, 9) — with alphabetically sorted machine names, and a `dim` legend line (`Machines: A = name, B = name`). The legend noun comes from `FormatOptions.machineLegend` (default `Machines`; `Users` when `-u all --by-machine` keys the columns by user) via `renderMachineLegend(columns, label)` (svlv, shared data-sized width 260828-7x4i)
- Machine columns MUST include per-machine totals in the Total row
- Machine columns MUST be omitted in compact mode regardless of `machineCosts` presence
- `emitCsv(data, kind, opts)` (`src/node/tui/formatter.ts`) MUST render three kinds — `"snapshot"`, `"history"`, `"total-history"` — as RFC 4180-compliant CSV on stdout. Rules: first line is a header row, comma separator, LF (`\n`) terminator (no CRLF), no BOM, no ANSI/no bars/no delta arrows. String fields containing `,`, `"`, or newlines MUST be quoted with `"` and internal `"` doubled. Numeric fields render raw (no thousands separators). Cost fields use two decimals with no `$` prefix. A final `Total,...` row follows when more than one tool has visible data (`visibleCount > 1`). Snapshot header: `tool,tokens,input,output,cache,cost` (`cache` is write + read combined; machine columns still follow `cost`). History header: `date,input,output,cache_write,cache_read,total,cost`. Total-history header: `date,{tool1},{tool2},...,total` with **every** registry tool column retained — the zero-cost column omission does not apply to CSV, because scripts may index columns positionally (rows sorted by date ascending). Date labels use ISO format (`YYYY-MM-DD` or `YYYY-MM`)
- `emitMarkdown(data, kind, opts)` MUST render the same three kinds as GitHub-flavoured Markdown tables on stdout. Rules: output begins with a `## {title}` heading line (titles match ANSI renderer titles — `Combined Usage ({period})`, `{toolName} ({period})`, `Combined Cost History ({period})`; the period parenthetical carries the `, last 3 months` cap hint when `opts.capActive` is set, via the shared `periodLabel` helper — see the cap-hint bullet above), followed by a blank line, then a GFM table (header row, alignment separator, data rows). String columns left-aligned (`:---`); numeric columns right-aligned (`---:`). Numeric values keep comma thousands separators (human readability). Cost values use `$` prefix with two decimals and thousands separators (via `fmtCost`). The total-history table applies exact-zero column omission (all-`$0.00` columns drop; the ANSI pivot's significance rule does not apply here — see the omission bullet above). A `**Total**` row with bolded numeric values is appended when `visibleCount > 1`. No ANSI, no inline bars, no delta arrows. Trailing newline at end of output
- Machine columns in CSV MUST append after base columns as `machine_{name}_cost` per machine, sorted alphabetically by machine name (via `collectMachineNames`)
- Machine columns in Markdown MUST append after base columns using the machine name directly as the header (no A/B/C letter codes, no separate `Machines:` legend line — GFM output is paste-ready and doesn't need the width-conservation letter coding used by the ANSI renderer)
- Output-format dispatch MUST happen once per dispatch function: `fetchAllHistory` / `fetchToolMerged` / `fetchToolSnapshot` runs exactly once, then a single `switch (outputFormat)` selects `emitJson`, `emitCsv`, `emitMarkdown`, or the existing `print*` renderer. Duplicating fetch logic across format branches is prohibited
- In daily history views (`renderHistory`, `renderTotalHistory`, non-compact ANSI only) a dim divider line MUST be emitted before each data row whose label's `YYYY-MM` prefix differs from the previous row's — same construction as the header divider (`divStr + costDiv + machineDiv + barDiv` for `renderHistory`; `divStr + costDiv + barDiv` for `renderTotalHistory`). No separator before the first row; separators are computed on the post-`maxRows` visible window. Compact mode, CSV, and Markdown emitters carry no separators (260815-oojd)
- The row whose label equals `currentLabel(period)` (imported from `src/node/core/fetcher.ts` — local-time semantics covering daily/weekly/monthly) MUST render its label cell in `boldWhite` (the Total-row emphasis color) in both history renderers, non-compact ANSI only. The marker is color-only — padded cell width is unchanged and `--no-color`/`NO_COLOR` strips it automatically (260815-oojd)
- In daily history views (both history renderers, non-compact ANSI only) a row whose label falls on a Saturday or Sunday MUST render its date cell in `dim` — the date cell only; cost/token cells and the bar stay full-intensity. The weekday comes from the `isWeekendLabel` helper (`new Date(label).getUTCDay()` — ISO date-only labels parse as UTC midnight, so the weekday is timezone-independent). The current-period marker wins when both apply: a weekend today renders `boldWhite`, never `dim` (one cell, one style). Monthly and weekly periods, compact mode, and the CSV/Markdown emitters carry no weekend dimming; `--no-color`/`NO_COLOR` output is byte-identical to undimmed output (260816-kw96)
- Both history renderers MUST append one dim summary footer after the Total row (non-compact ANSI only, only when ≥2 data rows — the Total row's own condition): `avg ${cost}/{day|week|month} · [this month ${cost}] · peak ${cost} ({label})`. `avg` = window total / number of data rows, unit suffix per period; `this month` = sum of current-calendar-month rows, daily period only, omitted when the window has no current-month rows; `peak` carries the max row's label in parentheses. CSV and Markdown emitters carry no footer (260815-oojd). When the pivot renders bars with ≥2 visible tools and color enabled, the pivot footer MUST append a legend group — one colored `█` swatch plus dim tool name per visible tool in column order (e.g. `· █ Claude Code █ Codex █ Kimi`), each swatch in the tool's `STACK_PALETTE` color with resets that neither bleed into nor strip the surrounding dim styling; the legend is omitted when color is disabled, when bars are suppressed (narrow terminal), or when only one tool column is visible (260816-3tah)
- History bars MUST scale on the field selected by `FormatOptions.metric` (`BarMetric = "cost" | "tokens"`, absent ≡ `"cost"`): `barValue(e, metric)` yields `totalCost` or `totalTokens`. `renderHistory` feeds those values to `computeBarScale`/`renderScaledBar` and to the footer; `renderTotalHistory` keeps a cost map (cells, Cost column, Total row — always cost-denominated) alongside a bar map (per-tool bar values), so the row bar total and the stacked per-tool segments follow the metric while the table cells do not. Footer stats (`avg`/`this month`/`peak`/`p95`) receive the same values as the bars and format through `fmtMetric(value, metric)` — `fmtCost` under cost, `fmtNum(Math.round(value))` under tokens (e.g. `avg 3,200/day · peak 9,000 (2026-06-02)`). With the metric absent or `cost`, output is byte-identical to a metric-less render; compact mode, CSV, and Markdown ignore the metric (svlv)
- Bar scaling in both history renderers MUST use a two-zone piecewise scale when `maxCost > 1.5 × p95`, where `p95` is the 95th percentile (linear interpolation over sorted ascending **nonzero** visible row costs) — via the exported `percentile`/`computeBarScale`/`renderScaledBar` helpers in `src/node/tui/formatter.ts`. Below the trigger (including windows with no nonzero costs) the single-zone path delegates to `renderBar` and output is byte-identical to it. When active the bar area splits into: main zone (linear 0→p95, width `barWidth − overflowZone − 1` — fill is solid green in the single-tool history and per-tool stacked segments in the pivot, see the stacked-bar bullet), a single dim `┊` (U+250A) scale-break rule rendered in every row at the same column (short bars space-pad up to it), and an overflow zone (width `max(4, round(barWidth / 4))`, linear p95→maxCost, solid yellow and unsegmented, only rows with `cost > p95` — yellow is reserved exclusively for this zone). Rows at exactly p95 end at the rule. Total bar width is unchanged; when active the summary footer appends `┊ = ${p95} (p95)` (260815-oojd, overflow/yellow reservation 260816-3tah)
- The pivot's row bar (`renderTotalHistory`) MUST fill its main zone — or the whole bar in a single-zone window — with contiguous per-tool colored segments, left to right in pivot column order, each segment's character count proportional to that tool's share of the row cost: the exported `apportionSegments(shares, total)` helper apportions by largest-remainder rounding over the bar's visible character count (ties break by column order) so segments sum exactly to the unstacked bar's length, and `renderStackedScaledBar(rowTotal, toolCosts, colorFns, scale, barWidth)` colors each contiguous run of the already-rendered bar string (stripping ANSI yields bytes identical to the unstacked bar). The fractional-eighths final character belongs to the last (rightmost) segment with ≥1 char; a tool whose share rounds to zero characters gets no segment. Segment colors come from `STACK_PALETTE = [green, magenta, blue, cyan]` assigned in visible column order — green leads so the first (dominant) column matches the single-tool history bar, and yellow is excluded (reserved for the overflow zone); a 5th+ visible tool renders uncolored. `renderBar`/`renderScaledBar` remain single-segment primitives; the single-tool history bar renders solid green with no segmentation and no legend (260816-3tah, palette order 260816-w61k)

## Design Decisions

- **Render/print split**: `render*` functions return `string[]` for compositor consumption in watch mode. `print*` wrappers exist for direct one-shot output. This avoids duplicating rendering logic.
- **Fractional bar precision**: Using 8 Unicode block widths per character cell gives smooth visual resolution without requiring half-line tricks.
- **Delta via callback**: Watch mode passes `prevCosts` map from the previous poll cycle. Keys use `"{toolName}:{label}"` for history entries and plain `"{toolName}"` for snapshots. This keeps the formatter stateless.
- **Bar metric rides `FormatOptions`, defaulting to cost** (svlv): `--metric` becomes `FormatOptions.metric` and reaches every history renderer (one-shot and watch) through the same `withCap` merge that carries `capActive`; an absent field means cost. *Why*: one seam for all flag-derived render options, and the cost default keeps every existing invocation byte-identical (Constitution § Output Stability). Only bars, stacked segments, and the footer follow the metric — the single-tool table already shows a `Total` tokens column, and switching the pivot's cells would be a larger stability break. *Rejected*: tokens-by-default; a separate token-history renderer (second code path). *Introduced by*: 260826-svlv-all-users-aggregate-token-bars
- **Space-less delta indicator in the pivot** (260703-gmcp): `deltaIndicator` gained a `noSpace` param; `renderTotalHistory` alone passes `noSpace = true` so the arrow abuts the Cost cell (`$128.13↑`, +1 char) instead of the spaced ` ↑` (+2). *Why*: the full 6-tool pivot row's minimum width is 96 chars (every cell ≤ `$9,999.99`), so a 2-char indicator would render 98 and wrap on a 96–97-col terminal — and a wrapped row breaks the watch-mode compositor's `contentHeight` line-counting. The +1 space-less form keeps that minimum at 97. Other renderers have width headroom and keep the spaced arrow. A companion `indicatorReserve` term reserves the extra char in the `barWidth` budget when `prevCosts` is set, so the fix holds across the bars band too — *Rejected*: fixed-width pivot columns (overflow 80 at five tools). (This entry's original *Rejected* also ruled out hiding zero-data columns on Output Stability grounds; that position is reversed by the zero-column-omission decision below — the CSV contract plus a minor version bump now covers the stability concern.)
- **Progressive column layout**: Tables measure column widths and compute remaining space for bars, enabling graceful degradation on narrow terminals. `renderHistory` uses fixed widths (D=12 for dates, N=14 for numbers); `renderTotal` uses 12 for both the Tool column and its numerics (see the snapshot Cache-column requirement above). The cross-tool pivot (`renderTotalHistory`) is the exception: it sizes tool columns **per-tool** (`max(name.length, MIN_TOOL_COL_WIDTH=9, longest cell incl. the Total-row sum)`, Date `PIVOT_DATE_WIDTH=10`) rather than a fixed width, because at five tools a fixed 14-wide column overflowed the 80-col terminal — see the pivot width-contract requirement above (260703-gmcp, floor 260815-q6fx).
- **Unified rendering**: Watch mode and non-watch mode produce identical table output. The compositor stacks the stats grid above the table output without modifying it.
- **CSV vs. Markdown numeric conventions** (260423-lx0g): CSV targets machine consumers (spreadsheets, `awk`/`cut` pipelines) — raw numbers with no thousands separators, costs without `$`, snake_case `machine_{name}_cost` column headers sorted alphabetically. Markdown targets humans (PRs, Slack, docs) — commas in numbers, `$` prefix on costs, machine names used directly in headers, `**Total**` row bolded to match the ANSI renderer's `boldWhite` convention. Each format optimises for its paste target rather than sharing a single numeric rendering path.
- **CSV/MD output always strips ANSI, inline bars, and delta arrows** (260423-lx0g): Bars are terminal-visual affordances, and delta arrows only have meaning in watch context. Both are useless (or actively harmful) in CSV/MD paste targets.
- **Markdown output always includes a `## {title}` heading** (260423-lx0g): The dominant paste targets (GH PRs, GH issues, internal docs) benefit from the heading; removing it post-hoc is trivial (`tail -n +2`), adding one is more work. A `--no-heading` flag is listed as a non-goal for this change but is an easy follow-up if requested.
- **Cap heading hint via a `capActive` FormatOptions/EmitOptions field, not by mutating `period`** (260717-yuuj): the `last 3 months` hint is threaded as an optional `capActive: boolean` on `FormatOptions`/`EmitOptions`, consumed only at the four heading-render points through a shared `periodLabel(period, capActive)` helper. *Why*: `period` drives `currentLabel`/`aggregateForPeriod`/label-column logic and must stay pure — a boolean touched only where the heading is built keeps table + Markdown uniform without perturbing any data computation. *Rejected*: appending ` last 3 months` to the `period` string handed to renderers (would corrupt every `period`-keyed computation). The hint appears wherever a heading exists (ANSI tables + Markdown); CSV/JSON have no heading so none is added — the cap itself still applies to their data upstream via the defaulted `sinceFlag`. The hint explains why the default daily/weekly Total row is now a 3-month total rather than all-time.
- **Negligible and zero-cost pivot columns are omitted in human-facing formats**
  **Decision**: The ANSI pivot (`renderTotalHistory`) keeps a tool column only when its total across the visible labels is ≥ $1.00 and ≥ 0.1% of the window grand total (`significantCostTools`, boundary values kept), falling back to the exact-zero filter (`nonzeroCostTools`) and then the unfiltered registry list; `emitMarkdownTotalHistory` keeps the exact-zero rule (`nonzeroCostTools` over all its labels); CSV keeps all columns.
  **Why**: With 6 registered tools and typically 1–2 active, ~80% of the table was `$0.00` noise; the dead columns pushed the full row past 80 chars, breaking the 80-col fit and suppressing the inline bar chart (`MIN_BAR_AREA`) at 90–100-col terminals. The snapshot renderer already omits zero-token tool *rows* — the same precedent applied to columns. Output Stability is preserved where it matters: CSV (the machine contract) keeps positional columns, and the ANSI/Markdown change ships with a minor version bump per the constitution.
  **Rejected**: Dimming the zero columns (keeps the width problem); always rendering every registry column in human-facing formats — the always-render rule adopted in 260703-gmcp is reversed here, its machine-stability concern now served by the CSV contract plus the minor version bump.
  *Introduced by*: 260815-q6fx-pivot-zero-columns-cost-separators
- **Pivot zero-column filter keys on the post-maxRows visible window**
  **Decision**: The ANSI filter sums costs over the labels actually displayed (after `maxRows` truncation), not all fetched labels; Markdown filters over all its labels (the emit path has no `maxRows`).
  **Why**: Matches what the user sees; avoids ghost columns for tools active only outside the truncated watch window. The compositor re-measures every frame, so a column legitimately appearing mid-watch (tool crosses $0 → nonzero) is a safe layout change; delta keys (`total:{label}`) are label-based and unaffected.
  **Rejected**: Filtering on all fetched labels (ghost all-`$0.00` columns in the watch window).
  *Introduced by*: 260815-q6fx-pivot-zero-columns-cost-separators
- **Current-period marker keys on `currentLabel(period)` uniformly**
  **Decision**: The marker highlights the row whose label equals `currentLabel(period)` from `src/node/core/fetcher.ts`, for every period (daily → today, weekly → this week, monthly → this month).
  **Why**: One code path covers the daily + monthly cases and weekly falls out for free; `currentLabel` already encodes the local-time label logic and importing it introduces no import cycle (fetcher does not import the TUI layer).
  **Rejected**: A local `todayLabel` helper in formatter.ts — duplicates existing logic (code-quality anti-pattern); a `todayLabel` FormatOptions field — extra pathway with no consumer needing an override.
  *Introduced by*: 260815-oojd-history-month-anchors-p95-bars
- **Two-zone geometry: overflow = max(4, round(barWidth/4)), rule 1 char, main = remainder**
  **Decision**: Fixed split derived from `barWidth`; main zone scales `0→p95`, overflow scales `p95→maxCost`.
  **Why**: At the minimum bars-shown width (10) this leaves main 5 / rule 1 / overflow 4 — both zones stay legible; at MAX_BAR_WIDTH 30 it gives main 21 / overflow 8, matching the intake mock's proportions.
  **Rejected**: Percentage-only split with no floor (overflow collapses to 1–2 chars at narrow widths, making $1k vs $4k indistinguishable again — the exact failure the feature fixes).
  *Introduced by*: 260815-oojd-history-month-anchors-p95-bars
- **Snapshot shows one combined Cache column at 12-wide columns**
  **Decision**: `renderTotal` (and the Markdown/CSV snapshot emitters) carry a single combined `Cache` column (write + read) between `Output` and `Cost`; the snapshot's fixed widths are 12 for both the Tool column and the numerics, landing the full row at 87 chars.
  **Why**: `Tokens` includes cache, so without the column the visible breakdown appeared off by orders of magnitude (cache dwarfs input+output on real Claude Code data) and read as a bug; the combined column closes the row arithmetic with data already on `UsageTotals`, and 12-wide cells still hold `999,999,999,999`.
  **Rejected**: Separate Cache Write / Cache Read columns (single-tool-history granularity, too wide for an at-a-glance snapshot); a compact `487.7M (99% cache)` token treatment (departs from the snapshot's tabular idiom); keeping 14-wide columns (99-char rows past the ≤90 budget).
  *Introduced by*: 260815-nda3-snapshot-cache-token-visibility
- **Stacked pivot bars color the already-rendered bar character sequence**
  **Decision**: `renderStackedScaledBar` first computes the row's raw bar string exactly as the unstacked path (`renderBar`/`renderScaledBar` against the same scale and zone widths), then apportions that string's visible characters among tools via `apportionSegments` (largest remainder) and colors each contiguous run.
  **Why**: Reusing the already-rendered character sequence makes the "segments sum exactly to the unstacked bar length" invariant structural — stripping ANSI provably yields identical bytes — and keeps `renderBar` the single-segment primitive.
  **Rejected**: Rendering each segment independently via per-tool `renderBar` calls — per-segment eighths rounding drifts the total length by ±1 char against the unstacked bar.
  *Introduced by*: 260816-3tah-stacked-tool-bars-pivot
- **Weekend annotation dims the date cell only, never the row**
  **Decision**: Saturday/Sunday rows in daily history views dim just the date cell, through the same `labelCell` seam the today marker uses (today → `boldWhite`, else weekend → `dim`, else plain).
  **Why**: Weekend usage data is not less important — the annotation marks calendar position, explaining the weekly sawtooth at zero width cost. Reusing the existing date-cell styling seam adds no new code path.
  **Rejected**: Whole-row dimming (visually demotes real cost data); week separator lines (considered alongside the month-anchor separators and skipped as too heavy — cell dimming is the quiet version).
  *Introduced by*: 260816-kw96-dim-weekend-dates-history
- **Stack palette leads green, assigned positionally — never by cost rank**
  **Decision**: `STACK_PALETTE[0]` is `green`, assigned to the first visible pivot column like every other slot — the "dominant tool gets green" outcome falls out of registry order (Claude Code first), not a cost computation.
  **Why**: Keeps the pivot chart green-dominant, matching the single-tool history bar's identity, while staying deterministic — a tool's color never changes across windows, days, or cost shifts, preserving day-to-day comparability.
  **Rejected**: Assigning green dynamically to the highest-cost tool — colors would swap mid-history whenever another tool overtook Claude Code, and the legend would disagree across renders.
  *Introduced by*: 260816-w61k-green-dominant-stack-palette
- **Cyan on palette slot 4, blue on slot 3**
  **Decision**: The full order is `[green, magenta, blue, cyan]` — slot 3 (Gemini in the shipped registry) is blue, slot 4 (Kimi) is cyan.
  **Why**: ANSI blue is the muddiest color on dark backgrounds so it goes to the rarest tool; Kimi appears more often than Gemini in real data, so it gets the more legible cyan. Yellow stays excluded — reserved for the overflow zone.
  **Rejected**: `[green, magenta, cyan, blue]` (Gemini cyan, Kimi blue) — viable, but gives the more legible color to the less-used tool.
  *Introduced by*: 260816-w61k-green-dominant-stack-palette
- **Output-Stability version bumps happen at release time, not in the feature diff**
  **Decision**: A change that alters stable CLI output does not edit `package.json`; the constitution's minor-bump obligation is satisfied by cutting the next release as `just release minor` (`scripts/release.sh` owns the version field and release commits), with the PR body noting "requires minor release".
  **Why**: Release commits are separate in git history; bumping the version field inside a feature PR collides with the release automation.
  **Rejected**: Bumping `package.json` in the feature PR — fights the established release flow.
  *Introduced by*: 260816-3tah-stacked-tool-bars-pivot
- **Cost and machine columns are data-sized with a fixed floor**
  **Decision**: Every right-aligned cost column (the pivot Cost and per-tool columns, `renderHistory`'s Cost column, `renderHistory`/`renderTotal` machine columns) is sized via the shared `costColumnWidth(values)` helper = `max(COST_WIDTH, longest fmtCost() the column will hold, including its Total-row value)`, computed from the pre-collected row data before the bar budget; 9 stays as the floor.
  **Why**: Byte-identical output for every render whose cells fit 9 chars; columns grow only when needed and never overflow at any magnitude, so cost decimal points and bar starts sit at one column index on every row including the Total. The pivot's per-tool `toolWidths` already established data-sizing.
  **Rejected**: A larger fixed constant (e.g. 11) — steals bar characters from every small-cost render and breaks again at `$1,000,000.00`.
  *Introduced by*: 260828-7x4i-cost-column-autosize-dim-zeros
- **All machine columns share one width**
  **Decision**: Machine columns in `renderHistory` and `renderTotal` share a single `machineColWidth` rather than sizing each independently.
  **Why**: The letter-coded A/B/C columns read as a uniform block; one width variable keeps the `mcols.length × (w + 3)` budget arithmetic.
  **Rejected**: Per-column sizing — saves at most a char or two of bar width for extra bookkeeping.
  *Introduced by*: 260828-7x4i-cost-column-autosize-dim-zeros
- **Negligible thresholds are ANSI-pivot-only with a two-level fallback**
  **Decision**: `significantCostTools` keeps a pivot column iff its visible-window total is ≥ $1.00 (`NEGLIGIBLE_COST_ABS`) and ≥ 0.1% of the window grand total (`NEGLIGIBLE_COST_SHARE`), boundaries kept; an emptied set falls back to `nonzeroCostTools`, then to the full registry list. Markdown stays on the exact-zero rule; CSV is unfiltered.
  **Why**: A `$0.04` column costs ~12 chars of bar area; the absolute floor handles tiny windows while the share handles org-scale windows where `$50` is noise. Markdown is paste-ready output where hiding a real nonzero column is more surprising than an extra column.
  **Rejected**: Share-only (a `$0.04` column survives a `$10` window); applying the rule to Markdown (silently drops nonzero data from a shareable table).
  *Introduced by*: 260828-7x4i-cost-column-autosize-dim-zeros
- **Zero-cell dimming tests exact `=== 0`**
  **Decision**: `costCell` dims a cost data cell only when its value is exactly `0`.
  **Why**: "Zeros are noise" targets absent data, not tiny spend; an exact-zero test is unambiguous and needs no epsilon.
  **Rejected**: Dimming anything that formats as `$0.00` — hides a real sub-cent spend.
  *Introduced by*: 260828-7x4i-cost-column-autosize-dim-zeros
